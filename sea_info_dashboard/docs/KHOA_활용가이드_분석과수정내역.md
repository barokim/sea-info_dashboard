## 3. 파일별 변경

### services.py — 실제 API 요청·응답 처리

**관측 요청에 시간 간격 명시:**

```python
OBSERVATION_INTERVAL_MINUTES = 1
if service == "OBSERVATION":
    params["min"] = OBSERVATION_INTERVAL_MINUTES
```

문서에서 `min`은 출력 시간 간격이며 기본값 1, 최댓값 60이다. 기존 코드는 생략해 기본값에 의존했다. 지금은 1분을 명시해 기존 최신 관측 해상도를 유지한다. 이것은 호출 주기나 자동 새로고침 주기가 아니다. `min=60`으로 바꾸면 출력 간격이 달라질 수 있으므로 최신값 목적과 비교한 뒤 결정한다. 조석 API의 명세에는 `min`이 없어 보내지 않는다.

**XML을 받을 때 처리:**

기본 요청은 계속 JSON이다. JSON 해석이 실패한 경우 KHOA 주소에 한해 `parse_khoa_xml()`을 사용한다. 가이드의 `<response><header>...<body><items><item>...`를 기존 JSON 파서가 읽는 구조로 변환한다. 단일 항목·여러 항목과 빈 XML 요소를 처리한다.

포털의 `OpenAPI_ServiceResponse/cmmMsgHeader/returnReasonCode` 오류도 해석할 수 있게 했다. 이 포털 오류 구조는 첨부 가이드의 정상 응답 예제와 별개로 추가한 방어 처리이며 실제 계정에서 발생한 오류를 관측했다는 뜻은 아니다. 잘못된 XML·DTD/엔티티 선언은 거부한다. WoRMS·Open-Meteo에는 이 XML 변환을 적용하지 않는다.

**문서 오류 코드에 맞춘 안내:**

| 코드 | 처리 |
|---|---|
| 0 / 00 | 정상; 본문 구조도 검증 |
| 3 / 03 | 데이터 없음, 빈 목록 |
| 10 / 11 | 잘못된 요청 변수 / 필수 변수 누락 |
| 12 | 서비스 주소·폐기 여부 확인 |
| 20 / 21 | 활용승인·접근 거절 / 키 일시 사용 중지 |
| 22 | 요청 한도 초과, 무조건 재시도하지 않도록 안내 |
| 30 / 31 | 미등록 키 / 기한 만료 |
| 32 / 33 | 미등록 IP / 서명 문제 |
| 40 / 41 | 관측소 / 관측 항목 일시 중지 |
| 1 / 2 / 4 / 5 / 99 | 제공기관 앱·DB·HTTP·시간 초과·기타 오류 |

기존에는 인증 일부 코드 외에는 일반 오류로 표시했다. 현재는 코드별 한국어 안내를 제공한다. 오류의 `resultMsg` 원문은 키·요청 주소 등이 섞일 가능성을 고려해 저장·화면에 그대로 전달하지 않는다. 누락되거나 숫자가 아닌 응답 코드도 정상으로 처리하지 않는다.

도우미 함수는 요청 한도에 429, 제공기관 시간 초과에 504, 나머지 외부 오류에 502를 사용한다. 대시보드에서는 기존 설계대로 이를 개별 카드의 `status=error`로 바꿔 부분 응답을 유지한다. 따라서 대시보드 HTTP 200만으로 모든 제공자의 정상 수신을 판단하지 않는다.

**추가 관측값 연결:**

| 가이드 필드 | 앱 응답 필드 | 단위 |
|---|---|---|
| `slntQty` | `salinity_psu` | psu |
| `atmpr` | `air_pressure_hpa` | hPa |
| `wndrct` | `wind_direction_deg` | deg |
| `maxMmntWspd` | `max_gust_speed_ms` | m/s |

기존처럼 해당 날짜의 마지막 관측 행에서 값을 가져온다. 그 행에서 누락된 값을 과거 행으로 몰래 채우지 않는다. 미제공·빈 값은 `None`, JSON에서는 `null`이며 실제 0과 구분한다.

### models.py — 응답 모델

`ObservationInfo`에 위 네 필드를 `float | None = None`으로 추가했다. 기존 필드를 유지하고 기본값이 있으므로 과거 데이터나 항목 미제공에도 대응한다. DB 테이블 변경은 필요 없다. 기존 조회 결과 JSON에 추가 항목이 저장된다.

### static/app.js — 화면 표시

관측 카드의 기존 수온·조위·풍속·기온에 염분·기압·풍향·최대순간풍속을 추가했다. 숫자와 단위를 표시하고 없는 항목은 기존 표시 함수로 `—`를 보여준다. 기존 반응형 그리드를 사용한다.

### test_main.py / test_khoa_guides.py — 회귀 검증

기존 통합 테스트에 추가 관측값이 API 응답과 저장 이력에 남는지 검증을 보강했다. 새 가이드 테스트에는 다음을 추가했다.

- 관측에만 `min=1` 전송, 날짜·페이지·JSON 요청 변수 검증
- 가이드의 XML 구조를 사용한 조석·관측 응답 해석
- 초가 생략된 시각과 극치 코드 1~4 해석
- 정상·자료 없음·인증·한도·일시 중지 오류 구분
- XML 포털 오류와 오류 원문 비노출
- 최신 관측 선택, 미제공 값과 실제 0 구분
- 잘못된 응답 코드·XML 거부

외부 API 응답은 모의 응답이다. 테스트는 실제 키 인증, 실제 수신 지연 또는 사진 식별 정확도를 검증하지 않는다.

2026-10-26 검증 결과: 기존 17개와 신규 8개를 합한 **테스트 25개 통과**, `static/app.js`의 Node.js 구문 검사 통과. 브라우저의 실제 데이터 표시와 본인 키 인증은 별도 확인 대상이다.

## 4. 의도적으로 추가하지 않은 항목

가이드에는 `crdir`(유향)과 `crsp`(유속)도 있다. `crsp` 명세는 단위를 m/s로 쓰면서 표본 값 46을 제시하고, XML 예제에서는 빈 항목이다. 실제 의미·단위와 제공 여부를 확인하기 전 임의 변환이나 유속 카드 추가는 하지 않았다. 기존 관측소 세 곳 외의 지역 확장도 이번 수정 범위에 포함하지 않았다.

## 5. 본인 인증키로 확인하는 순서

프로젝트에 `.env`가 없다면 아래와 같이 최초 생성한다. 기존 파일이 있으면 덮어쓰지 않는다.

```powershell
Set-Location C:\KBR\sea_info_dashboard
if (!(Test-Path -LiteralPath .env)) {
    Copy-Item -LiteralPath .env.example -Destination .env
}
```

로컬 편집기로 `.env`를 열어 `KHOA_API_KEY`에 본인의 일반 인증키(Decoding)를 입력한다. 서비스별 키가 다르면 `KHOA_TIDE_API_KEY`, `KHOA_OBSERVATION_API_KEY`를 각각 입력한다. 문서에 적힌 URL 예제 키를 복사하지 않는다. Decoding 키를 HTTP 클라이언트의 `params`로 전달하면 URL 인코딩은 클라이언트가 수행한다. 현재 코드는 Encoding 키도 한 번 디코딩해 처리한다.

```powershell
.\.venv\Scripts\python.exe -m unittest -v
.\.venv\Scripts\python.exe -m uvicorn main:app --reload --host 127.0.0.1 --port 8001
```

실행 중인 서버가 있으면 종료 후 다시 시작한다. 브라우저에서 `http://127.0.0.1:8001` 또는 `/docs`를 열고 인천·오늘 날짜로 조회한다.

확인 항목:

1. `/api/status`의 키 설정 여부와 `/api/dashboard`의 실제 `tides.status`, `observations.status`를 구분한다.
2. `ok`이면 관측소 이름·선택 날짜·관측 시각·단위가 일치하는지 본다.
3. 추가 항목이 없으면 `—`가 정상일 수 있다. 관측소별 모든 항목 제공을 가정하지 않는다.
4. 오류라면 카드의 코드별 안내를 보고 승인·기간·IP·한도 등을 확인한다.
5. 미래 날짜에는 실측이 없으며 과거 날짜의 제공 가능 범위는 실제 응답으로 확인한다.

이번 수정에서는 본인의 실제 인증키를 제공받지 않았으므로 유효한 키를 이용한 실호출 검증은 수행하지 않았다. 코드 수정과 모의 응답 검증을 실제 활용승인·데이터 수신 성공과 구분한다.
