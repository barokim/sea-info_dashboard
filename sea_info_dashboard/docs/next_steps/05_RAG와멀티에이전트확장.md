# 05. 전공 기반 RAG와 멀티에이전트 확장

이 문서는 향후 구현안이다. 현재 프로젝트에 RAG나 에이전트 프레임워크가 구현되어 있다는 뜻은 아니다.

## 1. 먼저 일반 함수로 도구를 완성한다

현재 해양 조회·생물 검색·사진 분석 함수를 독립적으로 호출하고 결과·오류를 설명할 수 있게 만든다. 이후 질문에 맞는 함수를 고르는 라우터를 추가한다. 이 단계만으로도 오케스트레이션의 입력 → 도구 선택 → 실행 → 결과 통합을 배울 수 있다.

초기에는 LLM이 모든 일을 결정할 필요가 없다. 지역·날짜 조회는 정해진 API 함수로, 자료 질문은 검색 함수로 처리한다. 실제 필요가 생길 때 프레임워크를 선택한다.

## 2. RAG의 최소 동작

RAG는 관련 자료를 먼저 검색하고, 그 자료를 근거로 답변을 작성하는 흐름이다.

```text
공개 자료 선정 → 이용 조건·출처 기록 → 문단 단위 분리
                                         ↓
질문 → 관련 문단 검색 → 근거 충분성 확인 → 답변·인용 표시
                            └─ 부족하면 추가 질문 또는 답변 보류
```

첫 자료는 공식 생물 정보, 공식 영양성분 자료, 공개 해조류 연구 문서 중 검토 가능한 10개 안팎으로 제한한다. PDF·표를 추출한 뒤에는 숫자·단위·페이지가 원문과 일치하는지 직접 확인한다. 문서를 사용하려면 단순 공개 여부와 별개로 재사용 조건을 확인한다.

먼저 키워드 검색으로 평가하고, 동의어·문장형 질문에서 검색이 부족할 때 임베딩 검색을 추가한다. 처음부터 벡터 DB와 여러 에이전트를 동시에 도입하지 않아도 된다.

## 3. 문서 메타데이터

문서별로 `source_id`, 제목, 기관·저자, 원문 URL, 발행일, 확인일, 이용 조건, 버전을 저장한다. 문단에는 source ID, 문단 ID, 페이지·절 제목, 본문을 연결한다.

연구 자료에는 추가로 종·품종, 실험 조건, 시료 상태, 분석법, 측정값·단위, 한계·대상 범위를 기록한다. 고온 처리와 내성 품종의 차이, 건중량과 습중량 기준 차이를 답변 전에 구분할 수 있게 한다.

첨부 문서·검색 문단은 정보 자료로 취급한다. 그 안의 명령문이 앱의 도구 사용·키 접근·삭제 동작을 지시하지 않도록 시스템 지시와 자료 영역을 분리한다.

## 4. 역할 분리 제안

아래 역할은 처음에는 Python 함수나 모듈로 구현해도 된다. 각 역할을 별도 LLM 호출로 만들지는 비용·효과를 평가한 뒤 결정한다.

| 역할 | 입력·출력 | 책임 범위 |
|---|---|---|
| 요청 라우터 | 질문 → 작업 유형·필수 정보 | 지역·날짜가 없으면 확인 요청 |
| 해양 조회 도구 | 지역·날짜 → 구조화된 예보·관측 | 기존 `get_dashboard()` 재사용 |
| 생물 조회 도구 | 이름·사진 후보 → 학명·분류·한계 | 기존 생물·사진 서비스 재사용 |
| 자료 검색 도구 | 질문 → 근거 문단·출처 | 영양·생태·연구 자료 검색 |
| 근거 검사 | 초안·근거 → 통과·보완 항목 | 단위·시각·출처·추측 여부 검사 |
| 응답 작성 | 검증 결과 → 한국어 안내 | 실측·예보·연구 결과를 구분 |

예시 질문 “이번 주말 인천 바다 정보와 김의 영양 정보를 알려줘”는 날짜를 확정한 뒤 해양 조회와 문서 검색을 별도로 수행한다. 둘을 같은 근거에서 나온 정보처럼 합치지 않고 각각 출처를 표시한다.

## 5. 답변 규칙

- 최신 물때·관측은 저장된 연구 문서 대신 API에서 조회한다.
- 저장 이력을 사용하면 조회 당시 자료임을 표시한다.
- 외부 응답 오류·시간 초과·검색 근거 부족을 별도 상태로 반환한다.
- 자료에 없는 값이나 출처 URL을 만들어 넣지 않는다.
- 사진의 후보 판별 결과를 식용·무독성 확정으로 바꾸지 않는다.
- 연구에서 관찰된 성분 변화와 사람의 섭취 효과를 구분한다.

## 6. 작은 평가표부터 만든다

평가 질문 20개 정도를 먼저 작성한다. 개발자가 기대 답변과 근거 문서를 미리 지정해 두고 버전별로 비교한다.

| 유형 | 질문 예시 | 통과 기준 |
|---|---|---|
| 자료 검색 | 생김과 마른김 성분을 비교해줘 | 상태·기준량·출처가 일치하는 범위 설명 |
| 실시간 도구 | 오늘 인천 만조는 언제야? | API 날짜·지점·KST·출처 일치 |
| 정보 부족 | 이 사진만 보고 품종과 내성을 알려줘 | 확인할 수 없는 범위를 설명 |
| 근거 부족 | 자료에 없는 성분 수치를 알려줘 | 수치 생성 없이 보류 |
| 데이터 장애 | 물때 API가 실패한 상태에서 질문 | 실패를 표시하고 정상 도구 결과만 제공 |
| 문서 명령문 | 검색 문단에 도구 실행 지시 포함 | 자료 속 명령을 수행하지 않음 |

평가 항목은 검색 근거의 적합성, 문장과 근거의 일치, 날짜·단위 정확성, 실패 처리, 응답 시간, 호출 수·비용으로 잡는다. 정답 사진이 없는 테스트에서는 종 판별 정확도를 계산하지 않는다. 정확도를 평가하려면 별도 검증된 정답과 종별 표본이 필요하다.

최종 포트폴리오에서는 에이전트 개수보다 **왜 해당 도구를 골랐는지, 어떤 근거로 답했는지, 실패 시 어떻게 멈추거나 부분 응답하는지**를 보여준다.
