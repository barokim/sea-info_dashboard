# 01. 현재 상태와 개발 방향

## 1. 기획과 실제 구현 비교

기획서는 Streamlit 기반 UI를 제안하지만 현재 앱은 FastAPI와 HTML·CSS·JavaScript로 구성되어 있다. FastAPI CRUD 학습과 이어지도록 현재 구성을 유지하는 것을 권장한다.

| 기능 | 코드에서 확인한 상태 | 다음 작업 |
|---|---|---|
| 웹 대시보드 | `static/index.html`, CSS, `app.js` 있음 | 모바일·오류·대기 상태 점검 |
| 지역·날짜 조회 | 인천·부산·제주와 `/api/dashboard` 있음 | 한 지역부터 실제 응답 검증 |
| 만조·간조 | 국립해양조사원 호출·파싱 코드 있음 | 활용승인과 실제 인증 확인 |
| 수온·조위·바람 관측 | 관측 API 코드, 관측 시각·지연 표시 있음 | 결측과 오래된 자료 확인 |
| 시간별 파고·해수면 온도 | Open-Meteo 연결 코드 있음 | 모델 예보와 실측 구분 유지 |
| 생물 검색·상세 | WoRMS 검색, 학명·분류 조회 있음 | 국명 대응표의 출처 보완 |
| 사진 분석 | 이미지 검증·외부 AI·학명 대조·저장 코드 있음 | 실제 키와 사진으로 평가 |
| 관찰 기록 | SQLite CRUD 있음 | 기록과 사진 분석 결과 연결 |
| 조회 이력 | 결과 JSON·분석용 JPEG 저장 있음 | 이력 삭제·보관 범위 설계 |
| 영양·제철 정보 | 전용 API·화면은 미구현 | 소수 해조류부터 검증 데이터 작성 |
| 출처 기반 Q&A | RAG 전용 흐름 미구현 | 자료 선정·문서 검색부터 실습 |
| 계정·공개 운영 | 로컬 단일 사용자용 | 공개 전 접근 제어·사용량 제한 |

기존 README에는 공개 API 실호출과 모의 응답 테스트 결과가 기록되어 있다. 이번 현황표는 코드 확인이며 현재 외부 서비스의 정상 동작을 보증하지 않는다.

## 2. 코드 읽는 순서

| 순서 | 파일 | 학습 연결 |
|---|---|---|
| 1 | `models.py` | 자료형, 클래스, 요청 값 검증 |
| 2 | `main.py` | GET/POST/PATCH/DELETE와 요청·응답 |
| 3 | `database.py` | SQL, JSON 직렬화, 트랜잭션 |
| 4 | `services.py` | HTTP 요청, 날짜, 외부 JSON 변환 |
| 5 | `species_service.py` | 검색어 변환, 외부 ID·학명 연결 |
| 6 | `image_service.py` | 파일 검증, AI 호출, 결과 검증 |
| 7 | `static/app.js` | fetch, 비동기 요청, DOM 표시 |

먼저 `POST /api/records` 한 요청을 화면 → FastAPI → Pydantic → SQLite → 화면 순서로 따라간다. 이후 같은 방식으로 외부 API 요청을 따라간다.

## 3. 첫 완성본의 범위

**목표:** 사용자가 지역·날짜의 바다 정보를 확인하고, 사진에서 생물 후보를 살펴본 뒤 관찰 기록으로 남길 수 있다.

- 지역 세 곳을 유지하되 실제 연결 확인은 인천부터 진행한다.
- 물때·실측·모델 예보의 출처와 기준 시각을 각각 표시한다.
- 사진 분석은 후보와 식별 한계를 보여준다. 학명이 DB에 존재하는 것과 사진의 종 판별 성공을 구분한다.
- API 장애 시 해당 카드의 상태를 보여주고 다른 기능은 사용할 수 있게 한다.
- 재시작 후 기록을 다시 열 수 있고, 백업 DB를 복원할 수 있다.

제철 추천, 전국 지도, 로그인, 고급 RAG, 여러 AI 에이전트는 이 흐름을 완성한 뒤 차례로 확장한다.

## 4. 전공을 살리는 차별점

일반 해양 정보 대시보드 위에 **해조류 성분 정보 카드**를 추가한다. 시작 주제는 방사무늬 김을 포함한 소수 해조류로 제한한다. 종·품종·처리 조건·건조 상태·분석 단위·출처를 함께 보여주면 연구 경험을 서비스에 직접 연결할 수 있다.

예시 질문은 “생김과 마른김의 성분을 같은 기준으로 비교할 수 있는가?”, “고온 처리 조건에서 보고된 성분 변화는 어떤 실험 범위의 결과인가?”이다. 연구 결과를 일상 섭취 효과로 확대 해석하지 않고, 비교 가능성과 근거를 설명하는 콘텐츠로 만든다.

석사 연구 자료는 공개·사용 가능한 범위만 사용한다. 처음에는 공개 논문이나 공식 데이터의 요약 카드 5개로 시작해 구현 부담을 낮춘다.
